# テスト仕様書: AI要約・音声文字起こしWebアプリケーション

## 1. 概要

本書は、AI要約・音声文字起こしWebアプリケーションにおける機能検証および品質担保を目的としたテスト仕様書である。  
演習課題の要件に基づき、画面ごとの操作検証からバックエンドAPIの直接検証までを網羅し、正常系・異常系・境界値の各観点から動作確認を行う。

---

## 2. テスト対象と動作環境

### 2.1 テスト対象

- **フロントエンド**: `static/`（Vue.js 3 SPA、Bootstrap 5.3）
  - `HomeView.js`（要約入力、音声録音・文字起こし、要約スタイル選択、結果出力・ダウンロード）
  - `HistoryView.js`（履歴一覧、履歴復元、個別削除）
  - `AboutView.js`（アプリ情報表示）
  - `AppSidebar.js`, `AppToast.js`（ナビゲーション、トースト通知）
- **バックエンド**: `backend/app.py`（Flask REST API、ポート `5000`）
  - `/api/summarize`（テキスト要約API）
  - `/api/transcribe`（音声文字起こしAPI）
  - `/api/submit`（要約送信API）
- **外部依存・AIサービス**:
  - ローカル LLM: Ollama（`http://localhost:11434/api/generate`、モデル: `qwen3.5:0.8b`）
  - 音声認識: `backend/services/transcription.py`
- **クライアントストレージ**: ブラウザの `localStorage` / `sessionStorage`

### 2.2 テスト実施環境・事前準備

1. **Ollama の起動とモデルの準備**:
   ```bash
   ollama run qwen3.5:0.8b
   ```
2. **Flask バックエンドサーバーの起動**:
   ```bash
   cd backend
   python app.py
   ```
   （起動後、`http://localhost:5000/static/` でフロントエンドSPAも同時配信される）
3. **推奨テストブラウザ**:
   - Google Chrome（推奨）、Microsoft Edge、Mozilla Firefox、Safari
   - マイク機能検証のため、ブラウザでのマイク利用権限を許可できる環境であること

## 3. テストケースの記述項目と重点チェックポイント

### 3.1 記述項目

- **No**: テストケース通し番号
- **大項目**: 画面名または対象レイヤー（ホーム画面、履歴画面、共通UI、バックエンドAPI）
- **中項目**: 対象機能名（テキスト入力、要約実行、履歴復元など）
- **種別**: 重点チェックポイント区分（正常系、異常系、境界値）
- **事前条件**: テスト実施前の初期データ状態（履歴件数、Ollama稼働状態など。認証機能なしのためログイン状態は不要）
- **操作手順**: テスト実施者が行う具体的な操作手順
- **期待値**: システムの期待される動作、画面表示、HTTPステータス、エラーメッセージ、および目視確認観点
- **判定**: 検証結果の記録欄（`OK` / `NG` / `-`）
- **備考**: 特記事項、制限事項、タイムアウト値（60秒）などの補足

### 3.2 重点チェックポイント

- **正常系**: 一般的な入力・操作で仕様通り正しく動作すること。要約結果は「空文字でないこと」に加え「人間が見て目的を達成しているか」を目視評価する
- **異常系**: 未入力、タイムアウト、AIサーバー停止、デバイス権限拒否時などに適切なエラーメッセージ・トーストが表示され安全に復帰すること
- **境界値**: 空白文字のみ、特殊記号・XSSコード、最大文字数、最大保持件数（100件）などの限界値で破綻しないこと
